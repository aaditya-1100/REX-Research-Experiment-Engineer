## 4. REX-043 VERIFICATION — ADVERSARIAL INTEGRITY HARNESS

### 4.1 What was tested?
The 5 formal attack vectors in [`rex/evaluation/corruption.py`](rex/evaluation/corruption.py):
1. **Artifact Byte Tampering:** Appending bytes to disk file without updating DB SHA-256 hash.
2. **Result Metric Falsification:** Modifying `ResultModel.metric_value` in SQLite to `999.999`.
3. **Broken Evidence DAG Linkage:** Deleting an `EvidenceLinkModel` edge between claim and result.
4. **Ungrounded Claim Injection:** Inserting a claim with hallucinated metrics lacking supporting results.
5. **Cross-Run Evidence Injection:** Attempting to link a claim from Run A to an evidence node from Run B.

### 4.2 What does the test prove?
- In 100% of cases, the [`DeterministicVerifier`](rex/evidence/verifier.py) or [`EvidenceGraphService`](rex/evidence/graph.py) detects the attack, rejects the mutation, and marks the run `VerificationStatus.FAIL` with detailed error traces.

### 4.3 Uncovered Attack Paths
- **Concurrent File Mutation during Hash Verification:** Time-of-check to time-of-use (TOCTOU) file race if an artifact is modified while being hashed.
- **Floating-point Subnormal / NaN Injection in Analysis JSON:** While canonical JSON dumps handle NaN/Inf by raising errors, dirty JSON strings inserted directly via raw SQL could bypass Pydantic validation.

## 8. SECURITY BOUNDARY AUDIT

1. **Evidence Isolation:** Verified. Cross-run links between claims and results are blocked with `CrossRunEvidenceError`.
2. **Run Isolation:** Verified. Separate `ResearchRunModel` instances maintain distinct foreign-key namespaces.
3. **Database Isolation:** Verified in tests via in-memory SQLite instances.
4. **Execution Isolation (Docker):** Fragile.
   - When Docker is available, `DockerExecutionBackend` applies `--network none`, `--memory 2g`, `--cpus 2`, and read-only root filesystems.
   - When Docker is unavailable, the runner raises `DockerUnavailableError` (fail-closed).
   - **Crucial Rule:** We must NEVER fall back to un-sandboxed host execution for untrusted agent code. A secure fallback (e.g. rootless Podman, gVisor, or WebAssembly) must be formally designed.
5. **Prompt Injection Boundary:** Literature titles and abstracts are cleaned via regex heuristics in [`rex/literature/trust.py`](rex/literature/trust.py). However, adaptive multi-turn jailbreaks against frontier LLMs have not been red-teamed.
